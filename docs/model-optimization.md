# Model optimization evaluation plan

This is a bounded research plan, not a claim of measured model acceleration. No weights were downloaded, trained, compressed or substituted during this work. Keep current model and quality defaults until a candidate passes the same complete-video evaluation as its baseline. Guidance was checked against primary Apple documentation on 2026-10-01; record the actual coremltools version when conducting experiments.

## Establish the actual model contract first

`CoreMLModelRegistry.swift` names x2, x4 and x8 Real-ESRGAN resources and validates one Float32 NCHW RGB input/output, batch 1, square input tiles larger than the 16px overlap, and output dimensions equal to input dimensions multiplied by the registered native scale. Registry entries do not establish that weights are present. The engine reads actual tensor shapes from model metadata and validates them before inference.

Tests include contracts `[1,3,256,256] → [1,3,1024,1024]` for x4 and `[1,3,64,64] → [1,3,512,512]` for x8. These are tested layouts/release-sample expectations, not evidence that every distribution contains those weights. The x2 test includes `[1,3,128,128] → [1,3,256,256]`; inspect its real metadata before treating it as a supported release artifact. Hash the actual source weights and converted package, capture tensor strides, normalization, color space, native scale, conversion options and license provenance.

The engine always predicts at the model's native scale and then resizes to the requested output scale. With an x8 model requested at x2, native output contains `(8/2)^2 = 16` times the requested pixel area before downsampling. That ratio describes output storage/conversion work; it is **not** a 16× inference-latency claim. The x8 tile64 contract also requires more overlapping input tiles than tile256 for the same frame. Compare native x2 candidates first for x2 output, without silently changing the user's model choice.

## Prioritized experiments

| Approach | Needed assets/work | Controlled experiment and limitation |
| --- | --- | --- |
| Better model selection | Licensed existing weights; conversion and contract checks | Compare native x2/x4 choices and compact SR candidates at identical requested size. Quality, unsupported operators and actual Apple hardware placement decide suitability; parameter count alone does not. |
| Weight quantization | Original `.mlpackage`/ML Program or convertible source weights | Begin with isolated 8-bit weight-only variants, then optional 4-bit per-block trials. Keep Float32 external tensor contract. Weight storage precision and activation precision are separate. |
| Palettization | Same source; optional calibration data | Compare 8-bit and 6-bit LUT variants before 4-bit. Grouped-channel variants are candidates within the macOS15 target. Smaller files may decompress into ordinary runtime weights; benchmark memory and latency separately. |
| Activation quantization | Representative calibration data; sometimes fine-tuning | Evaluate W8A8 only after weight-only baselines. Calibration must include dark areas, saturated colors, grain, text and tile borders. Check device-specific support and macOS15 compatibility. |
| Structured pruning | Training graph/data and usually fine-tuning | Distinguish sparse masks/block or n:m sparsity from physically removing channels. Channel removal changes dependent layers and requires architecture conversion. Do not apply aggressive zero-shot pruning to unknown SR weights. |
| Distillation | Teacher, student architecture, licensed dataset and training budget | Train a smaller native-scale student with reconstruction/perceptual/feature supervision, then compare video artifacts. Distillation is a training project, not a toggle on a compiled model. |
| Operator fusion / graph cleanup | Convertible graph and numerical reference | Inspect converter passes and deployment graph for redundant transposes/casts and eligible fusion. Standard conversion already performs graph optimization; do not assume manually fusing nonlinear residual blocks is equivalent. |
| Structural reparameterization | Architecture supporting equivalent branch folding; often retraining | Fold eligible linear branches into deployment convolutions and check numerical equivalence before compression. Arbitrary Real-ESRGAN nonlinear branches cannot simply be collapsed. |
| Evolutionary search | Candidate space, held-out data, substantial evaluation/training budget | If pursued later, bound trials and optimize quality, actual Mac latency and peak memory together. A small deterministic search over existing compression configurations is a more practical first step. No search/training ran here. |

Apple distinguishes data-free, calibrated and training-based compression; hardware/runtime behavior varies. Use [Apple's workflow](https://apple.github.io/coremltools/docs-guides/source/opt-workflow.html), [quantization guide](https://apple.github.io/coremltools/docs-guides/source/opt-quantization-overview.html), [palettization guide](https://apple.github.io/coremltools/docs-guides/source/opt-palettization-overview.html), [pruning algorithms](https://apple.github.io/coremltools/docs-guides/source/opt-pruning-algos.html) and [pruning performance caveats](https://apple.github.io/coremltools/docs-guides/source/opt-pruning-perf.html). Check each exported model's deployment target, rather than assuming a macOS27 SDK makes newer model operations backdeployable. Converter [PassPipeline documentation](https://apple.github.io/coremltools/source/coremltools.converters.convert.html) explains existing cleanup/fusion options.

Research directions are supported by primary examples, not transferable benchmark promises: [SR knowledge distillation](https://arxiv.org/abs/2111.10988), [RepVGG structural reparameterization](https://arxiv.org/abs/2101.03697) and [regularized evolutionary architecture search](https://arxiv.org/abs/1802.01548). The latter two papers do not establish gains for this app's SR models.

## Acceptance and reproducibility

1. Freeze a small licensed set of stills and short videos, including motion, faces, text, animation, compression damage, grain, dark scenes and tile seams. Keep calibration/training images separate from held-out evaluation. Preserve color handling, codec, input/output size, scale, overlap, feathering and frame timestamps between variants.
2. Record conversion time, package size, cold compile/load time, warm prediction p50/p95, tiles/frame, preprocessing/blending/resize/encode time, complete-video throughput, peak process memory and cancellation behavior. Warm up first, alternate candidate order, repeat trials and record chip, OS, Xcode/coremltools, power/thermal state and compute-unit configuration.
3. Compare `.all`, `.cpuOnly`, `.cpuAndGPU` and `.cpuAndNeuralEngine` where available. These configurations do not force every operation onto a single device. Inspect [MLComputePlan](https://developer.apple.com/documentation/coreml/mlcomputeplan-1w21n) and Instruments for actual placement/copies; estimated plan costs do not replace wall-clock measurements. Never label a GPU/ANE result from configuration alone.
4. Measure PSNR/SSIM on suitable reference pairs and perceptual quality separately; perform blind crop review for detail loss, false texture, color shifts, halos, border seams and flicker/temporal instability. Use motion-aware temporal consistency checks on video. Freeze acceptable quality loss and required performance gain before selecting a winner; metrics alone cannot establish restoration quality.
5. Preserve original artifacts and an immediate rollback path. Verify source code, weights and dataset rights independently, retain [Real-ESRGAN credits/license](https://github.com/xinntao/Real-ESRGAN/blob/master/LICENSE), and document transformation settings and hashes for every candidate. A paper's publication or code license alone does not establish redistribution rights for its weights/data.

No model latency, quality, compression ratio, CPU/GPU/ANE placement or model-specific memory improvement has been measured in this checkout. Native video I/O regression timings elsewhere in the repository exclude AI inference and must not be cited as model performance.
